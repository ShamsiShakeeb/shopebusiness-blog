How a multi-tenant ecommerce platform with subdomains works

One application, many isolated stores

In a multi-tenant design a single deployment serves every store. The incoming host header — shop1.shopebusiness.com, shop2.shopebusiness.com — is resolved to a tenant, and every query from that request is scoped to that tenant's data. Shop-E-Business does this on ASP.NET Core (.NET 8) with Entity Framework Core and SQL Server, using a CQRS layer (separate command and query handlers dispatched through a mediator) so read paths stay lightweight and write paths stay explicit. New stores are provisioned automatically the moment a merchant signs up: no DNS tickets, no per-store deployment.

Subdomain by default, custom domain when you want it

Every store is instantly reachable on its subdomain. Merchants who own a domain can attach a custom domain to their store; the platform maps that hostname to the same tenant, so product slugs, SEO metadata and the admin panel all resolve under the merchant's brand.

Subscription and licensing at the tenant level

Access is enforced per tenant with a subscription check on protected routes. Bangladesh merchants pay 499 Tk/year locally; international merchants activate with a Gumroad license key ($10/year) that is verified server-side against Gumroad's license API. No recurring card subscription is involved.

Lightweight headless ecommerce for small businesses — do you actually need headless?

"Headless" separates the storefront frontend from the commerce backend and connects them through APIs. It is powerful for large brands with dedicated frontend teams. For a small business it usually means: a second codebase, a build pipeline, a hosting bill for the frontend, and a developer on call. The goal people are chasing — fast pages, clean markup, full control of the look — can be achieved without decoupling anything.

What Shop-E-Business does instead

  • Server-rendered storefronts (Razor views) with minimal JavaScript — pages arrive complete, no client-side hydration wait.
  • Theme presets (Classic, Fashion Luxe, Grocery) driven by a shared layout model, so the look changes without changing the platform.
  • Client-side cart and price cache in cookies/localStorage for instant totals without extra round trips.
  • Media on object storage (Cloudflare R2) so product images are served from a CDN-backed origin rather than the app server.

You get the lightweight result headless promises, with the operational simplicity of a hosted, turnkey platform.
