Short answer: To connect an ERP to an online store, receive each new order from the store through an API, create it in the ERP, and send fulfilment status back. On Shop-E-Business (Tier-2, $18/year), the Expose API posts every new order to your HTTPS endpoint with a signed JWT, and your integration updates delivery and payment status through POST /api/exposure/order-status.

Integration flow

  1. Buyer places an order on your store.
  2. Shop-E-Business calls your endpoint with a JWT carrying CustomOrderId and shop.
  3. Your service verifies the token (RFC 7519 (JSON Web Token)) and creates the sales order in the ERP (for example via the Odoo external API docs).
  4. When the ERP ships, post DeliveryStatus and DeliveryTrackingUrl back.

API contract

EndpointDirectionPurpose
Order dispatchShop-E-Business → your HTTPS endpointNew order, HS256 JWT (CustomOrderId, shop), 5-minute expiry
POST /api/exposure/order-statusYou → Shop-E-BusinessCustomOrderId, DeliveryStatus, DeliveryTrackingUrl, PaymentStatus
GET /api/exposure/courier-configYou → Shop-E-BusinessShip-from address and default parcel size/weight

Both directions use HS256 with one shared 48-byte secret per shop, shown in Advance → Expose API and regenerable at any time. C# and Node.js signing samples are provided.

Design tips

  • Use CustomOrderId as the idempotency key so retries never duplicate ERP orders.
  • Keep the shared secret in your server's secret store.
  • Map statuses to a shared vocabulary such as schema.org Order order status.

Running it serverless: Cloudflare Workers docs. Full contract: Expose API and Worker developer guide.
